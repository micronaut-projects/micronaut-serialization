Micronaut Serialization includes support for reading and writing https://github.com/toon-format/spec[TOON] (Token-Oriented Object Notation) documents with the `micronaut-serde-toon` module.

Add the following artifact to the `dependencies` block:

dependency:micronaut-serde-toon[groupId="io.micronaut.serde",scope="implementation"]

NOTE: The TOON mapper is tree-based: it reads the whole document into a `JsonNode` before deserializing, unlike the streaming YAML and JSON mappers.

The TOON mapper is exposed as a named api:serde.ObjectMapper[] bean. Inject it with the `toon` qualifier, or by its concrete type api:serde.toon.ToonMapper[], when you want to read or write TOON data:

snippet::example.ToonReportService[project-base="doc-examples/example-toon", source="main"]

With the correct dependencies in place, define a serializable type:

snippet::example.ToonLibrary[project-base="doc-examples/example-toon", source="main"]

Once you have a type annotated with ann:serde.annotation.Serdeable[], the mapper serializes objects into compact, human-readable TOON format:

[source,text]
----
name: City Library
books[2]:
  - title: The Stand
    authors[1]: Stephen King
  - title: VALIS
    authors[1]: Philip K. Dick
----

== Tabular Representation

Uniform collections and maps are serialized using TOON's tabular representations, minimizing token overhead:

[source,text]
----
items[2]{id,name,price}:
  1,Widget,9.99
  2,Gadget,19.99
----

Keyed tabular objects are also supported for uniform map structures:

[source,text]
----
users[2:]{age,role}:
  alice: 30,admin
  bob: 25,user
----

== Interoperability

The TCK checks, in both directions, that documents are exchanged with the JToon (`dev.toonformat:jtoon`) 2.0.4 library for: tabular arrays, keyed tabular objects (`[N:]{...}`), nested field groups (`{a{b,c}}`), numbers in scientific notation (below `1e-6` or from `1e21`), and `#` comment lines on input. No compatibility option is needed for these shapes. The mapper and JToon also agree on every TOON specification encode and decode fixture that applies to the mapper, on string and key quoting for each delimiter, and on decoding of the common document edge cases. They differ in these ways:

* A `BigInteger` outside the `long` range is written as a quoted decimal string, the same as JToon. JToon reads such a value back as a string; the mapper reads an unquoted integer beyond the `long` range as a `BigInteger` or `BigDecimal`, while JToon reads it as a string or a `double`.
* JToon 2.0.4 accepts length markers (`[#3]`) and whitespace between a field name and its nested field group (`{x {y}}`). The mapper rejects both, as the specification does.

Other TOON implementations may not support all of them, depending on the specification version they target.

== Configuration

TOON formatting is configured under `micronaut.serde.format.toon`:

[configuration]
----
micronaut:
  serde:
    format:
      toon:
        delimiter: COMMA
        indent: 2
----

`delimiter`:: Selects the delimiter for array and tabular rows. Supported options are `COMMA` (default), `TAB`, and `PIPE`.
`indent`:: Number of spaces per indentation level when writing. The default is 2.
`max-input-size`:: Maximum number of bytes of TOON input read when decoding. Larger input is rejected with a api:serde.exceptions.SerdeException[]. By default there is no limit.

== Decoding Leniency

Decoding is more lenient than the TOON specification's strict mode in two ways:

* Indentation is not checked against the configured `indent`, which only affects encoding. The decoder infers the indent step from the first nesting transition in the document and requires every later transition to use the same step. A document indented with 4 spaces throughout is accepted when `indent` is 2.
* Blank lines are rejected only between two rows, entries or items of a declared-count array body, or between a list item's continuation fields. Blank lines elsewhere are skipped.

Declared array lengths and field-list widths are still checked exactly.

== Security and Limits

TOON parsing respects `micronaut.serde.maximum-nesting-depth` to guard against stack exhaustion from maliciously deep input structures.

The decoder reads the whole input into memory and builds a complete `JsonNode` tree before deserializing, and the encoder builds a tree before writing. Memory use therefore grows with document size. Set `micronaut.serde.format.toon.max-input-size` to reject input above a given number of bytes; this is recommended when decoding untrusted input such as LLM output or request bodies.
