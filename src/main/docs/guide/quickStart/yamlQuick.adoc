Micronaut Serialization includes support for reading and writing YAML documents with the `micronaut-serde-yaml` module.

Add the following artifact to the `dependencies` block:

dependency:micronaut-serde-yaml[groupId="io.micronaut.serde",scope="implementation"]

NOTE: `micronaut-serde-yaml` uses the event based parser and emitter of `snakeyaml-engine` only as a token source and sink. Object mapping is performed by Micronaut Serialization's build-time serializers and deserializers, and neither SnakeYAML's object construction nor Jackson Databind is involved.

The YAML mapper is exposed as a named api:serde.ObjectMapper[] bean. Inject it with the `yaml` qualifier, or by its concrete type api:serde.yaml.YamlObjectMapper[], when you want to read or write YAML data. When `micronaut-serde-jackson` is also present, Jackson remains the primary JSON mapper:

With the correct dependencies in place, define a serializable type:

The mapper reads and writes the same types supported by Micronaut Serialization. The example model is written as:

== Reading YAML

A document may have a mapping, a sequence or a scalar as its root node, so a `List<Book>` reads from a top-level sequence and a `String` from a bare scalar. Exactly one document is read: an explicit `---` start marker and `...` end marker are accepted, but a second document in the same input is rejected. Empty input is rejected as well.

Plain scalars are typed with the YAML 1.2 core schema. Quoted scalars are always strings, integers may be written in decimal, octal (`0o17`) or hexadecimal (`0x1F`) notation, and `.inf`, `-.inf` and `.nan` are read as the non-finite floating-point values. Numbers that do not fit a `long` or a `double` keep their precision when read into a `BigInteger` or `BigDecimal`. Mapping keys must be scalars; complex keys written with the `?` indicator are rejected.

Anchors, aliases and merge keys are resolved while reading:

[source,yaml]
----
defaults: &defaults
  timeout: 30
  retries: 3
service:
  <<: *defaults
  retries: 5
----

An alias replays the anchored node, including any aliases or merges that were resolved inside it. A merge key `<<` splices the entries of the referenced mapping, or of each mapping in a referenced sequence, into the enclosing mapping. A key the mapping defines itself always wins over a merged key, wherever in the mapping it is written, and a mapping earlier in a merged sequence wins over the ones after it, as the merge key specification requires. Unknown properties, including nested mappings and sequences, are skipped like they are for JSON.

NOTE: Because the keys a mapping defines are only all known once the mapping ends, merged entries are read at the end of the enclosing mapping. That is invisible for beans and records, and only changes the iteration order of a `Map` read from a mapping that uses a merge key. Jackson Databind instead lets a merged key override a key written before the merge key; Micronaut Serialization follows the specification here.

== Read Features

YAML read behavior is configured under `micronaut.serde.format.yaml.read-features`:

[configuration]
----
micronaut:
  serde:
    format:
      yaml:
        read-features:
          boolean-as-strings: true
          empty-string-as-null: true
          code-point-limit: 3145728
----

`boolean-as-strings`:: When enabled, legacy YAML boolean-like values such as `yes`, `no`, `on`, and `off` are read as strings. The canonical `true` and `false` values remain booleans. Disable it to interpret the legacy values as booleans.

`empty-string-as-null`:: When enabled, an empty plain scalar such as `key:` is read as `null`. Disable it to read the value as an empty string. Quoted empty strings remain strings.

`code-point-limit`:: The maximum number of characters a single YAML input may contain. Larger input is rejected before it is parsed, which bounds the memory an untrusted document can claim. The default is 3 MiB. The nesting depth of documents is bounded by `micronaut.serde.maximum-nesting-depth` like it is for the other formats, and alias expansion is capped so that recursive or exponentially expanding documents fail instead of consuming memory.

== Write Features

YAML write behavior is configured under `micronaut.serde.format.yaml.write-features`. All available settings can be configured together as follows; normally, only settings that differ from their defaults need to be specified:

[configuration]
----
micronaut:
  serde:
    format:
      yaml:
        write-features:
          write-style: BLOCK
          indent: 2
          explicit-start: false
          explicit-end: false
          minimize-quotes: true
          literal-block-style: false
          split-lines: true
          canonical-output: false
          indent-arrays: false
          indent-arrays-with-indicator: false
          allow-long-keys: false
          use-yaml-nonfinite-notation: true
----

=== Document and Collection Layout

`write-style`:: Selects `BLOCK` or `FLOW` collection output. For example, flow style writes a mapping containing a sequence as `{values: [A, B]}`.

`indent`:: Controls the number of spaces used for each nested mapping level. The default is two.

`explicit-start` and `explicit-end`:: Add the YAML document markers `---` and `...`, respectively:

[source,yaml]
----
---
key: value
...
----

`canonical-output`:: Forces canonical YAML output. Collections use explicit flow syntax, scalars are quoted, mapping keys use `?`, and the document starts with `---`:

[source,yaml]
----
---
{
  ? "key"
  : "value",
}
----

`indent-arrays`:: Adds one space before block sequence indicators:

[source,yaml]
----
values:
 - A
 - B
----

`indent-arrays-with-indicator`:: Indents sequence indicators by two spaces and includes that offset when aligning nested sequence content. When both array indentation features are enabled, this setting takes precedence:

[source,yaml]
----
values:
  - A
  - B
----

`allow-long-keys`:: Raises the simple-key limit from 128 to 1024 characters. Without it, longer keys are written with YAML's explicit `?` key syntax; with it, eligible long keys remain in `key: value` form.

=== Scalar Formatting

`minimize-quotes`:: Omits quotes from strings when YAML permits. Strings that would otherwise be read back as another type, such as `true`, `null` or `123`, and strings containing YAML indicators stay quoted. Disable it to write strings such as `hello world` as `"hello world"`. Multiline strings are written in literal block style while quotes are minimized.

`literal-block-style`:: Writes multiline strings in YAML literal block style even when `minimize-quotes` is disabled:

[source,yaml]
----
text: |-
  Hello
  World
----

`split-lines`:: Allows long double-quoted strings to wrap across lines. Disable it when quoted strings must remain on one output line.

`use-yaml-nonfinite-notation`:: Writes non-finite floating-point values as `.nan`, `.inf`, and `-.inf`. Disable it to use `NaN`, `Infinity`, and `-Infinity` for compatibility with Java-oriented consumers.

Documents are always written with `\n` line breaks so the output is identical on every platform.

== HTTP

The module registers a message body handler for `application/yaml` (RFC 9512) and the legacy `application/x-yaml` media type, so controllers and clients can consume and produce YAML bodies:

[source,java]
----
@Post(uri = "/books", processes = YamlMediaTypes.APPLICATION_YAML)
Book save(@Body Book book) {
    return book;
}
----

The constants api:serde.yaml.YamlMediaTypes[]#APPLICATION_YAML and api:serde.yaml.YamlMediaTypes[]#APPLICATION_X_YAML are provided for convenience. JSON stays the default for content negotiation; YAML is selected by the request `Content-Type` and `Accept` headers.

== Limitations

* Only one document per input is supported.
* Mapping keys must be scalars.
* Explicit YAML tags are honoured for the core schema types (`!!str`, `!!int`, `!!float`, `!!bool`, `!!null`); other tags are read as strings and no tags are written.
* Anchors and aliases are not written. Repeated object references are serialized as copies, and the Jackson `USE_NATIVE_OBJECT_ID` and `USE_NATIVE_TYPE_ID` features have no equivalent.
